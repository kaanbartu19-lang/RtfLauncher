# RtfLauncher V7.1 — Profile / Browse Content / Skin Fix

This pass keeps the existing Minecraft launch, Modrinth download, Electron IPC, OAuth and navigation architecture intact.

## Profile UI
- Right-side full-height profile rail.
- Created profiles appear immediately in the rail and remain selected.
- Selected profile uses an active state and shows a Play hint.
- Profile detail follows the supplied Modrinth-style instance layout: header, Play/settings/more actions, Content/Files/Worlds/Logs/Share tabs and centered empty-content state.
- Profile data is read from the local launcher config; legacy `profiles` data is migrated to `modProfiles` when present.

## Browse Content
- Browse content opens directly into a Modrinth-style browser.
- Tabs: Mods, Resource Packs, Data Packs, Shaders.
- Search, sort, page size and pagination are retained.
- Result rows show icon, author, description, downloads, follows, Minecraft version, loader and update information.
- Installed projects are disabled and shown as installed.
- Profile content is stored in the selected instance's own folder.

## Skin Upload
- Native browser file selection is used in the renderer.
- PNG is validated in the Electron main process.
- Accepted sizes: 64x64 and 64x32.
- Skin is stored under the user's stable UUID/id/username fallback and reloaded on startup.
- Existing pickSkin IPC remains for compatibility.

## Dependency policy
- `skinview3d` remains exactly 3.4.2 in the lockfile.
- No `npm update` or `npm audit fix --force` was run.
- No dependency version was changed.
