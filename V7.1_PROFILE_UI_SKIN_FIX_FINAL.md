# RtfLauncher V7.1 — Profile UI / Browse Content / Skin Upload Fix

Scope intentionally limited to the requested stability/UX fixes.

## Profile / Instance UI
- Right-hand, full-height profile rail.
- Profiles are local launcher instances; the instance page does not require a server profile lookup.
- Selecting a profile opens the instance-style header with Play/settings/options and Content/Files/Worlds/Logs/Share tabs.
- Empty Content view matches the supplied reference structure: No content installed + Upload files + Browse content.
- Browse Content opens directly into the Modrinth-style search/list layout with Mods, Resource Packs, Data Packs and Shaders tabs.
- Installed projects are blocked from a second install using per-profile metadata and filesystem checks.

## Skin upload
- Uses the existing Electron `skin:pick` IPC path rather than sending raw file data from renderer to main.
- Existing 64x64 / 64x32 validation is preserved.
- Stored PNG is reloaded after restart.

## Preserved systems
- Minecraft launch chain was not rewritten.
- Modrinth global mods page was not rewritten.
- Cosmetics backend was not changed.
- Navigation was not changed.
- skinview3d remains 3.4.2 (`^3.4.2` in the existing manifest).

## QA
Static QA passes in this environment. Real Windows runtime/build/installer/Minecraft tests require a connected Windows environment and are not claimed as PASS here.
