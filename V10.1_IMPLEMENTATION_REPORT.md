# RtfLauncher V10.1 — Profile / Content / Onboarding Runtime Fix

## Changed
- Kept `skinview3d` locked at the existing package/lock version: 3.4.2. No dependency update.
- `CharacterPreview.jsx` uses `SkinViewer.controls`, `ResizeObserver`, `setSize()` and `dispose()`; there is no `createOrbitControls` import.
- Reworked first-run onboarding into a multi-step flow: welcome, language, theme, account, Minecraft/loader/RAM, performance, 3D skin, automatic RtfSMP client preparation, summary and finish.
- Onboarding persists its current step and selections in launcher config.
- Microsoft and Offline/Cracked account choices are integrated into onboarding without removing the existing login systems.
- The default `Rtf SMP` profile is created/updated through the existing main-process `ProfileStore`, then the selected profile is used for content installation.
- Existing profile rail/content browser architecture is preserved and visually strengthened as a persistent right-side rail.
- Added first-run reset controls in Settings. Reset First Run does not delete profiles/instances/content/skins; Reset First Run + Accounts also clears saved auth.
- Added a short post-onboarding RtfLauncher opening animation.
- Updated displayed launcher version to v10.1.

## Existing V10 systems preserved
- Profile persistence in `profiles.json`
- Right-side profile rail
- Profile-specific instance directories
- Content browser with Modrinth search, pagination, sorting, compatibility and install states
- Duplicate prevention by project ID/hash
- Resource packs, data packs and shaders content types
- Skin pick → validate → preview → apply persistence
- Microsoft OAuth + safeStorage
- Electron contextIsolation/nodeIntegration/sandbox security
- Profile-specific Minecraft launch
