# RtfLauncher V7.1 — Profile / Content / Skin Fix

This pass targets the UX shown in the supplied reference screenshots while preserving the existing Minecraft launch and Modrinth systems.

## Changed
- Profile page now manages local Minecraft instances instead of requiring `/api/profile/:uuid`.
- Profiles appear in a right-side rail.
- Selecting a profile opens an instance-style header with Play, settings/folder access, delete, and Content/Files/Worlds/Logs/Share tabs.
- Content starts empty and provides Browse Content.
- Browse Content includes Mods, Resource Packs, Data Packs, and Shaders with Modrinth search, sorting, page size, pagination, one-click install, installed state, and removal.
- Profile content is stored per instance; the same Modrinth project cannot be installed twice into the same profile.
- Profile content metadata is stored in the profile instance so it survives launcher restarts.
- Profile Play uses the selected profile's version, Fabric version, instance directory, and the existing `mc:launch` chain. Profile mods are copied into that instance before launch.
- Skin upload now uses the Electron main process file picker, validates 64x64 / 64x32 PNG dimensions, stores the skin under the user's launcher data directory, and restores it after restart.
- Existing `skinview3d` version remains `^3.4.2`; `createOrbitControls` is not used.

## Not changed
- Microsoft OAuth flow
- existing global Modrinth mod download flow
- existing Minecraft launch implementation
- navigation structure
- cosmetics backend implementation
- dependency versions
