# RtfLauncher V7.2 — Profile & Content System Rebuild

## Scope
Rebuilt the existing profile/instance and per-profile content workflow without changing the Minecraft launch architecture, Microsoft OAuth flow, Electron isolation, or Modrinth API dependency model.

## Changed
- Profile store normalization and persistence/migration.
- Right-side profile/instance rail and selected-profile switching.
- Profile creation with real instance directory creation.
- Profile detail header with Play, Settings and overflow actions.
- Per-profile Content browser: Mods, Resource Packs, Data Packs, Shaders.
- Modrinth search, filters/sort, pagination, loading skeletons and detail/install states.
- Per-profile install metadata and filesystem-backed Installed state.
- Duplicate prevention by Modrinth project ID plus destination-file checks.
- Uninstall and metadata cleanup.
- Data Packs are world-specific and are never installed into the global mods folder.
- Real Upload Files flow with type validation.
- Files, Worlds and Logs panes use the selected instance directory.
- Profile-specific memory setting used by the existing launch path.
- Skin/3D viewer kept on the existing skinview3d version; resize uses the real container width/height and the existing viewer controls API.
- Removed any dependency on the unsupported `createOrbitControls` export.
