# RtfLauncher 8.0.0 — Real-Use Fixes Report

This pass keeps the existing release/update infrastructure intact and does not create or push any Git tag, GitHub Release, or commit.

## Root causes and fixes

### 1. Account reset
- Root cause: account reset did not clear all launcher-owned state and could leave profile/skin state behind.
- Fix: `account:reset` clears safe auth/session storage, resets the dedicated profile store (`profiles.json` + profile instances), removes the active user's persisted skin files, and rebuilds `config.json` without user/onboarding/personalization state.
- Global `%APPDATA%/.minecraft` is not deleted by this reset path.
- UI now shows the requested warning below the reset actions and requires two confirmations for account reset.

### 2. Language
- Root cause: a saved language value existed, but most renderer text was still hard-coded and there was no reactive cross-component localization layer.
- Fix: added lightweight in-project TR/EN i18n (`renderer/src/services/i18n.js`) with persisted config state and a `rtf:language` event for immediate updates.
- Main navigation, login, settings, onboarding, mods, skins, cosmetics and profiles now consume localized strings in the updated areas.

### 3. Skin upload / apply
- Root cause: skin IPC success responses did not consistently contain `success: true`, while the renderer checked that flag. Successful native picking/applying/loading was therefore treated as failure.
- Fix: corrected `skin:pick`, `skin:apply`/save, `skin:load`, and `skin:clear` result contracts.
- Existing PNG validation/model detection and `skinview3d` viewer are preserved.
- `CharacterPreview` only passes a valid explicit `slim`/`default` model to `loadSkin`; resize remains based on `ResizeObserver` + `viewer.setSize`.

### 4. Cracked / offline account flow
- Root cause: offline login and the RtfSMP server-account password step were separate and the onboarding path did not clearly complete the server credential step.
- Fix: offline onboarding now accepts the username and, when the configured RtfSMP API is present, the account password is requested and sent only to the authentication endpoint. The password is held in React state, is not written to `config.json`, and is cleared after successful login.
- Microsoft authentication continues through the existing secure flow.

### 5. Mod screen scrolling
- Root cause: fixed viewport/overlay sizing could cut modal content on shorter screens.
- Fix: modal backdrop is scrollable, modal content has a viewport-aware `max-height` and vertical scrolling, and page containers retain a safe minimum width/height behavior.

### 6. R logo in opening animation
- Root cause: the opening animation used a generic/incorrect R mark.
- Fix: opening/onboarding/finish branding now uses the existing `renderer/public/logo.png` RtfLauncher asset. No new third-party logo was introduced.

### 7. RtfShaders
- Root cause: the first-install required content list did not include the actual RtfShaders project.
- Fix: onboarding now prepares the real Modrinth shader project `rtfshaders` as profile shader content. The existing content manager routes shaders to `shaderpacks` and automatically prepares the Iris dependency for shader installs.
- Duplicate prevention remains handled by the existing profile content manager.

### 8. Profile icons
- Root cause: fallback profile marks were visually primitive.
- Fix: the existing profile rail now uses vector icon glyphs and improved selected/hover/border/shadow styling. Custom profile icon uploads remain supported.

### 9. Cosmetics preview scrolling
- Root cause: the preview pane could be visually clipped by an overly restrictive parent layout.
- Fix: the wardrobe preview is allowed to participate in the parent page scroll flow, while the 3D viewer keeps its own canvas bounds.

### 10. Customization screen
- Checked the current routes/components. There is no hidden, existing customization component waiting to be enabled. The existing `outfits`/Wardrobe route is already visible and currently acts as a placeholder for server-backed outfit persistence. No fake backend/customization system was added.
