# RtfLauncher V7.1 — Stability / UX Fix Pass

## Fixed
- Profile creation now stores Minecraft version, loader, loader version, icon, selected mods and timestamps.
- Created profiles now have a visible Play button and launch through the existing Minecraft IPC chain.
- Profile launches use isolated per-profile directories under the launcher application data directory and copy the selected installed mods into that profile before launch.
- Existing global/default Minecraft launch behavior remains unchanged when no profile directory is supplied.
- Added controlled profile-path IPC validation; renderer cannot choose an arbitrary filesystem path for profile launches.
- Fixed missing secure-auth preload bridge methods used by the existing App flow (`authSecureSave`, `authSecureLoad`, `authSecureClear`).
- 3D skin viewer now sizes itself from its real container with ResizeObserver and skinview3d `setSize`, avoiding CSS canvas stretching and handling window resize.
- Cosmetics now distinguish backend HTTP/auth errors instead of silently presenting an empty catalog.
- Equipped cosmetic ID is persisted locally through the existing launcher config; no fake backend equip/upload endpoint was introduced.
- Light UI polish: consistent profile form controls, profile action states, and slightly richer cards while preserving navigation/design language.
- Launcher titlebar version label updated from the stale `v3` text to `v7.1`.

## Intentionally unchanged
- Microsoft OAuth flow was not rewritten.
- Existing Modrinth search/download IPC was not rewritten.
- Existing Minecraft launch IPC remains the launch path.
- No production payment system was added.
- No fake cosmetics backend was added.
