# RtfLauncher V7.1 — Exact Modrinth Profile UX Fix

Changes are limited to the requested Profile/Instance presentation, Browse Content presentation, profile persistence guardrails, last-played metadata, and the skin upload UI fallback.

## Reference-driven UI changes
- Profile section is an instance manager with a persistent vertical profile rail on the right.
- The selected profile opens the instance view with the Modrinth-style header: large icon, name/version/loader line, Play, settings and overflow controls.
- Instance tabs: Content, Files, Worlds, Logs, Share.
- Empty content state mirrors the supplied reference with centered illustration, "No content installed", and Browse content / Upload files actions.
- Browse Content uses the supplied reference structure: top content-type tabs, wide search field, Sort by / View controls, pagination, and large content cards with install state on the right.
- Content types: Mods, Resource Packs, Data Packs, Shaders.
- Installed content is blocked from duplicate installation by project metadata and destination-file checks.

## Functional fixes
- Local launcher profiles are loaded from `modProfiles`; unrelated legacy profile objects are ignored.
- Profile creation persists the instance path and selected metadata.
- Successful profile launch records `lastPlayedAt` and persists the active profile.
- Skin upload now uses a real PNG file input and the existing secure Electron `saveSkin` IPC, while preserving the existing dialog IPC.
- Minecraft launch, Modrinth download IPC, preload isolation, and Cosmetics backend code were not rewritten.

## Validation
- Static QA: PASS.
- All renderer JSX files parsed successfully with the installed TypeScript compiler.
- Real Windows/Electron/Minecraft runtime remains an external test requirement in this environment.
